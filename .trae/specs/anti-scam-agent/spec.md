# 防割韭菜Agent - 产品需求文档

## 概述
- **摘要**：防割韭菜Agent是一个智能助手，通过大模型技术，帮助用户识别和防范投资陷阱、电信诈骗和非理性消费，为用户提供理性决策支持和风险预警。
- **目的**：解决用户在金融决策中因认知偏差和信息不对称导致的被割韭菜问题，提供客观、专业的风险评估和建议。
- **目标用户**：普通投资者、消费者，尤其是容易受到诈骗和非理性消费影响的人群。

## 目标
- 识别和预警投资风险，如庞氏骗局、高息诱惑等
- 防范电信诈骗，特别是汇款前的风险提示
- 提供消费决策建议，避免冲动消费
- 普及金融知识，提高用户防范意识
- 分析个人财务状况，提供合理的理财建议
- 接入大模型接口，提供智能问答和分析能力

## 非目标（范围外）
- 替代专业金融顾问的角色
- 提供具体的投资推荐
- 处理法律纠纷或追回损失
- 支持实时市场交易

## 背景与上下文
- 金融诈骗和投资陷阱日益增多，普通用户缺乏专业知识和识别能力
- 大模型技术的发展为智能风险评估和咨询提供了可能
- 用户在面对诱惑时往往难以控制自己的欲望，需要外力干预
- 传统的风险提示方式效果有限，需要更智能、个性化的解决方案

## 功能需求
- **FR-1**：投资风险预警 - 分析投资项目，识别潜在风险
- **FR-2**：电信诈骗防护 - 识别诈骗特征，阻止危险汇款
- **FR-3**：消费决策建议 - 分析消费行为，提供理性消费建议
- **FR-4**：金融知识普及 - 提供相关金融知识和防范指南
- **FR-5**：个人财务分析 - 分析用户财务状况，提供理财建议
- **FR-6**：大模型接口接入 - 支持多种大模型，提供智能问答
- **FR-7**：提示验证机制 - 用户通过验证后才能接入大模型接口
- **FR-8**：数据分析与可视化 - 生成风险评估图表和财务分析报告

## 非功能需求
- **NFR-1**：性能要求 - 响应时间在3秒以内
- **NFR-2**：安全性 - 保护用户数据隐私，加密存储敏感信息
- **NFR-3**：可用性 - 系统可用性达到99.9%
- **NFR-4**：可扩展性 - 支持新的大模型和功能模块集成
- **NFR-5**：用户体验 - 界面友好，操作简单，响应及时

## 约束
- **技术**：基于Web技术开发，支持PC和移动端适配
- **业务**：遵守相关金融法规和数据保护法规
- **依赖**：依赖大模型API，需要稳定的网络连接

## 假设
- 用户具备基本的网络使用能力
- 大模型API能够稳定提供服务
- 用户愿意提供必要的个人财务信息以获得更准确的分析

## 验收标准

### AC-1：投资风险预警
- **Given**：用户输入投资项目信息
- **When**：系统分析投资项目特征
- **Then**：系统识别潜在风险并提供预警信息
- **Verification**：`programmatic`
- **Notes**：系统应能识别常见的投资陷阱特征

### AC-2：电信诈骗防护
- **Given**：用户准备进行汇款操作
- **When**：用户向系统咨询汇款风险
- **Then**：系统分析汇款信息，识别诈骗特征并阻止危险操作
- **Verification**：`programmatic`
- **Notes**：系统应能识别常见的电信诈骗话术和特征

### AC-3：消费决策建议
- **Given**：用户输入消费计划
- **When**：系统分析消费行为和财务状况
- **Then**：系统提供理性消费建议，避免冲动消费
- **Verification**：`programmatic`
- **Notes**：系统应考虑用户的财务状况和消费习惯

### AC-4：金融知识普及
- **Given**：用户查询金融知识
- **When**：系统根据用户需求提供相关知识
- **Then**：系统提供易懂的金融知识和防范指南
- **Verification**：`human-judgment`
- **Notes**：内容应准确、易懂，适合普通用户

### AC-5：个人财务分析
- **Given**：用户输入个人财务信息
- **When**：系统分析财务状况
- **Then**：系统生成财务健康度报告和理财建议
- **Verification**：`programmatic`
- **Notes**：分析应基于用户提供的真实数据

### AC-6：大模型接口接入
- **Given**：用户完成提示验证
- **When**：用户请求智能问答服务
- **Then**：系统调用大模型API并返回智能回答
- **Verification**：`programmatic`
- **Notes**：系统应支持多种大模型，切换便捷

### AC-7：提示验证机制
- **Given**：用户首次使用大模型接口
- **When**：用户尝试接入大模型
- **Then**：系统要求用户完成提示验证，验证通过后才能使用
- **Verification**：`programmatic`
- **Notes**：验证方式包括密码、短信和问答验证

### AC-8：数据分析与可视化
- **Given**：用户请求风险评估或财务分析
- **When**：系统处理分析请求
- **Then**：系统生成风险评估雷达图、财务健康度仪表盘等可视化图表
- **Verification**：`human-judgment`
- **Notes**：图表应清晰易懂，数据准确
